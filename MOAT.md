# The moat

Which sources are worth recording, and which are not. Generated by
`tools/moat_study.py` from the registry's own `point_in_time` field, so it cannot
drift from what the code says. Last run 2026-08-06.

## The test

> Ask this source the same question in a year. Do we get today's answer back?

Where the answer is **yes**, recording is storage spent on a copy of something
the publisher hands anyone for free. Fourteen of Vintage's nineteen sources are
in that group, and they are the reason this file is short.

Where the answer is **no**, the history exists only because something was
running. That is not a licence anyone can buy, a page anyone can scrape late, or
an advantage anyone starting tomorrow can close. It only gets deeper.

## Worth recording

| Source | Prefix | Worth | What it buys | Why the publisher will not give it to you later |
|---|---|---|---|---|
| **sec-edgar-sic** | `sector:sic,` | highest | Point-in-time industry labels | EDGAR states the current SIC code and no date of change. Every cross-sectional neutralisation needs to know what industry a name was in *then*, and the alternative, GICS, is licensed from S&P and MSCI. Recording the code weekly builds the only free point-in-time classification there is. |
| **yahoo-finance** | `price:close` | high | Prices as they were printed | Every close is re-adjusted the morning after a split or dividend, so today's history is not the history anyone traded on. Recording the close as printed keeps the unadjusted series, which no free source has. |
| **apewisdom** | `ape:all-stocks,` | high | Retail attention history | There is no history endpoint and no vendor selling last Tuesday's board. A year of hourly reads is a year nobody starting today can have. |
| **sec-xbrl-frames** | `frame:us-gaap/Assets/CY2023Q1I` | high | Point-in-time cross-sections | A frame is every filer on one concept, carrying the accession but not its filing date. Snapshotting it dates the cross-section, which is exactly what a sort needs and what the endpoint refuses to give. |
| **ken-french-data-library** | `french:ff3,` | medium | Factor file vintages | The files are rebuilt on each release. A factor return can change with no record that it did, and a replication against today's file is not a replication of the paper. |
| **bls** | `bls:CUUR0000SA0` | low | CPI and payroll first prints | Same as BEA: worth having, already available with vintages through `fred:`. Record only if the FRED dependency becomes a problem. |
| **bea** | `bea:T10101` | low | GDP revision history | Real value, but ALFRED already keeps the vintages through `fred:`, so recording it duplicates a source that is already honest. |

## Already recording

`vintage.archive.targets` is the live list. Storage is not the constraint: the
four below write on the order of a hundred kilobytes a day before compression,
so a decade costs less than a phone's worth of photos. Continuity is the
constraint, and a missed week cannot be filled in afterwards.

| Target | Cadence | What is lost if it stops |
|---|---|---|
| `sector-sic` | weekly | EDGAR states a filer's current industry code with no date of change. Point-in-time industry labels are otherwise licensed, and every cross-sectional neutraliser needs one. |
| `ape-boards` | hourly | ApeWisdom publishes the present board only. There is no history endpoint and no way to buy last Tuesday. |
| `french-ff3` | monthly | The factor files are rebuilt on each release, so a number can change with no record that it did. |
| `price-as-printed` | daily | Yahoo re-adjusts every historical close the morning after a split or dividend, so today's history is not what anyone traded on. Recording the close as printed keeps the unadjusted series. |
| `frames-cross-section` | daily | A frame is every filer on one concept but carries no filing date. Snapshotting it dates the cross-section, which is what a sort needs and what the endpoint refuses to give. |
| `crypto-listings` | daily | Coinbase lists currently-traded products only. Recording the list is the only way to know what was tradable then, which is crypto survivorship. |

## Not worth recording

These keep their own history, so recording them buys nothing:

`sec-edgar-xbrl`, `sec-edgar-filings`, `open-source-asset-pricing`, `coinbase-exchange`, `finra-short-volume`, `ecb-reference-rates`, `cboe-indices`, `sec-form-25`, `us-treasury`, `cftc-cot`, `sec-form-13f`, `fred`.

## How it is stored

Append-only, bitemporal, gzipped JSONL partitioned by the UTC date of the read.

- A value identical to the last one recorded for the same
  `(entity, field, observed_at)` is not written again. An industry code that
  moves once a decade costs almost nothing; a mention count that moves hourly
  costs its full size.
- A partition is never rewritten once its day closes, so every file is immutable
  and cacheable forever.
- A source that cannot say when a value became public gets its `known_at` from
  the moment we read it, marked `vintage: recorded-at-read`. The row is not
  point-in-time back to its origin, and it does not claim to be. It is
  point-in-time from the day recording started.
